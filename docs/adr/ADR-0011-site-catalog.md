# ADR-0011：站点情报——内置目录先验 + 建议采纳流，而非新建"分组"实体

- 状态：Accepted（2026-09-06，IT2/v0.5.0）
- 关联：docs/v2-product-audit.md 竞品差距（Cold Turkey block lists）

## 背景

用户希望"像 Cold Turkey 默认有很多组，网站进来能自动识别分组和标签"。Cold Turkey 的机制：block lists（组）+ 组级例外 + 组日程，但**新站点仍需手动归组**。我们的机会：让系统对常见站点"开箱即知"。

## 备选

1. **新建 Group 实体**（组表 + 规则挂组 + 组预算/组日程）：模型完整，但与现有 Category 高度重叠，配置翻倍，用户要先理解"组 vs 类别"两层概念 → 否决（v2.0 阶段）
2. **目录先验 + 标签**（采用）：内置 `siteCatalog`（常用站点 → {名称, 组, 标签, 建议类别}），运行时按 host 后缀匹配；"组"是展示维度（键帽徽章），预算仍按类别（已有的、被验证的模型）
3. AI 分类：2.0 明确不做（PRODUCT.md 非目标）

## 决策

- `src/core/siteCatalog.ts`：内置 ~100 常用站（国际+国内），字段 `{ host, name, group, tags[], category }`；纯函数 `lookupCatalog(host)`（精确/后缀匹配，`www.` 归一）
- **建议采纳流**：当前段来自默认类别（无规则命中，`ruleId === undefined`）且目录可匹配时，popup 显示"未分类站点"建议卡：「example.com · 猜测：社交 → 娱乐 [采纳] [忽略]」；采纳 = 写入一条规则（新消息 `sw-add-rule`），下次起规则优先于目录
- 优先级不变：**显式规则 > 目录建议 > 默认类别**——目录永远不改变既有行为，只提供"下一步"的建议
- Options 规则表在名称列旁显示目录命中的组徽章（识别而非回忆，启发式 #6）

## 后果

- 无 AI、无网络：目录是静态数据，随扩展发布；冷门站无建议（可接受，规则仍可手写）
- 采纳的规则带 `group` 无持久化字段——组是目录推导的展示属性，规则本身保持 `{pattern, category}` 简单模型
- 目录数据会过时（站关了/转型）→ 影响仅限建议文案，无行为风险

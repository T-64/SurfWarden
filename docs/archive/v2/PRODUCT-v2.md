# SurfWarden（冲浪监督）产品方案

> 工作代号 SurfWarden，正式名待定。版本 v0.2，2026-09-06（v0.2：新增隐身窗口覆盖、引导页/学习目标、测试策略）

## 0. 一句话定位

一个**本地优先**的浏览器插件：自动记录你每天在什么网页上花了多少时间，用**内容级规则**（而不是域名一刀切）区分"刷 B 站"和"B 站学德语"，并通过预算、提醒、引导页来监督你——**拦下走神之后，把你带回去该去的地方**。

## 1. 背景与问题

用户痛点（真实场景）：

- 经常无意识刷 Twitter、看 Apex 直播，事后懊悔浪费时间；
- 但 B 站上看德语学习视频是**有益的**，不该被一起封掉；
- 冷火鸡（Cold Turkey）这类工具是**域名级**封锁：封 B 站 = 德语课也没了，不封 = 顺便刷了三小时；
- 统计类工具（Web Activity Time Tracker 等）只记录不监督，且同样按域名聚合；
- 还有一种最常见的走神：**不知道干嘛，手指自己输入了 bilibili.com**——事后才反应过来"我本来要干嘛来着？"；
- 隐身窗口是监督的天然后门："统计不到就开隐身刷"。

**核心矛盾：同一个域名，不同用途，价值完全相反。** 最典型的是 B 站——Apex 直播和德语课在同一个域名下。

## 2. 目标与非目标

### 目标

| # | 目标 | 衡量方式 |
|---|------|----------|
| G1 | 自动、准确地记录每个页面停留时间（含切走、发呆、锁屏） | 与实际使用误差 < 1 分钟/天 |
| G2 | 用规则把浏览行为归类，支持同域名下的内容级区分 | "B站德语课=学习，B站直播=娱乐"可配置且生效 |
| G3 | 监督闭环：预算 → 提醒 → 引导页 → 豁免 → 每日报告 | 预算超支后 30 秒内出现引导页 |
| G4 | 隐私：所有数据只在本地，无账号、无上传 | 代码中零网络请求（除可选的未来 AI 功能） |
| G5 | 覆盖隐身/InPrivate 窗口，不给监督留后门 | 隐身窗口内的浏览出现在当日统计中 |

### 非目标（v1 明确不做）

- ❌ AI 内容分类（架构预留接口，二期再说）
- ❌ 跨设备同步、移动端
- ❌ 对抗"用户禁用插件"的强对抗机制（报告里如实显示即可，不做军备竞赛）
- ❌ 团队/多人功能

## 3. 核心概念模型

这是整个产品的地基，五个概念 + 一个关键问题。

### 3.1 类别（Category）

浏览行为的最终归属，默认四类，可自定义：

- 📚 **学习**（如：B 站德语课、MDN、LeetCode）
- 💼 **工作**
- 🎮 **娱乐**（如：Twitter、Apex 直播）
- ⚪ **中性**（如：搜索引擎、GitHub 浏览）

每个类别可设：**每日预算**（分钟）、颜色。学习/工作类可以不设预算（正向指标，越多越好）。

### 3.2 规则（Rule）

把 URL（及后续的页面信号）映射到类别。一条规则：

```ts
{
  id: string
  name: string                    // "B站-德语UP主白名单"
  pattern: string                 // 见 3.2.1 匹配语法
  category: CategoryId
  specificity: 'exact' | 'path' | 'domain' | 'wildcard'  // 决定优先级
  enabled: boolean
}
```

**3.2.1 匹配语法**（P0 只需前三种）：

| 类型 | 语法示例 | 含义 |
|------|---------|------|
| domain | `twitter.com` | 该域名及所有子域名 |
| wildcard | `*.twitch.tv/*` | 通配符路径 |
| path | `bilibili.com/video/*` | 域名 + 路径模式 |
| regex | `^https://space\.bilibili\.com/(123|456)` | 高级用户用 |
| signal | 见 3.3，P1 | 页面内容信号 |

**3.2.2 匹配优先级**：specificity 分数 exact(10) > path(8) > domain(4) > wildcard(2)；同分按创建顺序。**更具体的规则永远赢**——这是"内容级区分"得以成立的前提。

**3.2.3 模板包**：内置常见站点模板，一键导入再改：
- 社交：twitter.com / x.com、instagram.com、weibo.com、xiaohongshu.com
- 视频：bilibili.com（默认娱乐）、youtube.com（默认娱乐）
- 直播：live.bilibili.com、twitch.tv、douyu.com
- 学习：coursera.org、leetcode.cn 等

### 3.3 双面站点问题（产品核心差异点）

B 站视频页 URL 是 `/video/BV1xxx`，**从 URL 看不出是德语课还是直播切片**。分三层解决，由轻到重：

| 层 | 方案 | 版本 | 说明 |
|----|------|------|------|
| L1 | **路径规则** | P0 | `live.bilibili.com/*` → 娱乐；`/video/BVxxx` 整段路径规则能覆盖部分场景 |
| L2 | **Popup 一键改判** | P0 | 打开 B 站发现是学习内容？点 popup 里"本次会话记为学习"，该会话重新归属 |
| L3 | **意图打卡 + 频道信号** | P1 | 打开双面站点时页面角落弹小条："学习 / 娱乐 / 取消"；或 content script 读 UP 主名，规则支持"UP 主 ∈ {白名单} → 学习"，选过一次自动记忆该 UP 主 |

L3 是无 AI 方案下最接近"理解内容"的手段：**用确定性信号（UP 主/频道名）+ 用户自标注**替代模型判断。

### 3.4 预算与监督动作（Budget & Action）

每个类别/规则可独立配置监督强度，**从软到硬**：

| 档位 | 行为 | 适用 |
|------|------|------|
| `track` | 只统计，不干预 | 学习、工作、中性 |
| `nudge` | 达预算 80% 弹非侵入横幅；每连续刷 30 分钟提醒一次 | 娱乐（默认） |
| `budget` | 预算耗尽 → 引导页（见 3.5） | 娱乐（可选开启） |
| `hard` | 无预算，直接全封，无豁免 | 例：你明令自己不看的站 |

**豁免**：引导页提供"再来 5 分钟"按钮，每天限 N 次（默认 2 次），豁免如实计入报告（"今天用了 2 次豁免"），不做道德审判但也不帮着隐瞒。

### 3.5 引导页（Guide Page）

预算耗尽访问该类站点时，`declarativeNetRequest` 把页面重定向到插件内页 `guide.html`。它**不是死胡同，而是一个岔路口**——把"默认选项"换成正向的那条路：

- 大字：今天该类别已用 X 分 Y 秒 / 预算 Z
- 本周趋势迷你图（"你最近 7 天平均刷 2.1 小时"）
- 🟢 **主按钮："去学习"——一键跳到你的学习目标（见 3.7）；15 秒无操作自动跳转（可关）**
- 次要位置：豁免按钮"再来 5 分钟"（剩余次数）、"查看今日报告"、退出

**行为设计出处**（前人智慧各取一块）：
- one sec 的强制暂停 → 超预算前的延迟与摩擦
- Intention 的意图询问 → "你本来想干嘛"式落地询问（P1，F12）
- Timewarp 类重定向插件 → 把人引向正路，而不是甩一张白墙
- 行为经济学的**默认选项效应** → 主按钮永远是正向那条路，豁免永远放次要位置

### 3.6 学习目标（Study Target）

针对"肌肉记忆型走神"（不知道干嘛 → 手指自己打开了 B 站），对策不是只拦，而是**给一条已经铺好的正路**：

- Options 里可配置若干"学习目标"：名称 + URL（如"德语课 A2" → B 站收藏夹/播放列表链接）
- 插件记住"上一次学习会话"的 URL，提供一键"继续上次的课"
- 出现位置：引导页主按钮、popup、（P1）新标签页替换页

### 3.7 隐身/InPrivate 窗口

"统计不到隐身窗口"等于监督有后门，必须覆盖：

- **技术边界**：Chrome/Edge 出于安全设计，不允许插件用代码强制开启隐身授权（企业策略除外，不适用个人场景）。所以采用**检测 + 引导**：首次安装引导页里检查 `chrome.extension.isAllowedIncognitoAccess()`，未开启则给三步图文指引（扩展详情页 → 详情 → 允许隐身模式），一次性的 10 秒操作
- 开启后（spanning 模式）`tabs` 事件照常上报隐身标签页，会话打上 `incognito` 标记，与普通窗口统一计入统计和预算
- badge 在检测到"未开启隐身授权"时常驻一个小黄点提示；报告的"未覆盖时段"（P2）会如实暴露缺口
- 隐私说明同步更新：本工具的设计目的就是**记录隐身浏览**（数据依然全部本地）

### 3.8 一天的边界

本地时区 0 点重置预算；**"一天结束时间"可配置**（默认 0 点，熬夜党可设为凌晨 4 点——凌晨 1 点刷的推算前一天）。

## 5. 关键用户流程

**首次安装（3 分钟内可用）**：
打开欢迎页 → 选模板包（社交/视频/直播/学习）一键导入 → 设置娱乐预算 45 分钟 → 按图文指引开启隐身授权（10 秒）→ 配置第一个学习目标（德语课链接）→ 完成。

**日常-学习**：打开 B 站德语视频 →（P1 弹打卡条选"学习"）/（P0 点 popup 一键改判）→ 计入学习，badge 变绿。

**日常-失控**：开 twitter → badge 从 🟢45 变 🟡9 → 弹横幅"娱乐预算剩 9 分钟" → 刷满 → 再开 twitter 落在引导页 → 主按钮"去学习"跳回德语课（或点次要的"再来 5 分钟"，第 1/2 次）→ 第 3 次引导页上只剩"去学习"和"看报告" → 关电脑。

**肌肉记忆走神**：不知道干嘛，手输 bilibili.com →（P1）呼吸 2 秒 + 落地询问"本来要干嘛" → 想起来了 → 点"带我去学习" → 直接落到课程页。整条链路 5 秒，比"先刷十分钟再自责"便宜得多。

**隐身窗口**：Ctrl+Shift+N 开隐身刷 twitter →（已授权）照常计入娱乐预算，popup 里该会话带隐身标记 → 预算耗尽照样落引导页。

**睡前**：打开报告页 → 今天学习 1.2h / 娱乐 47min / 豁免 1 次 → 连续第 5 天达标。

## 6. 技术方案

### 6.1 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 框架 | **WXT**（Vite 系插件框架） | MV3 开箱即用、HMR、content script UI 支持、未来可加 Firefox 目标 |
| 语言 | TypeScript | 全链路类型 |
| UI | React（popup / options / dashboard / guide 页） | 生态熟 |
| 存储 | **Dexie.js（IndexedDB）** 管数据；`chrome.storage.local` 管配置 | 明细数据量大且要按日期查询，`storage.local` 有配额且查询弱 |
| 封锁 | `chrome.declarativeNetRequest` 动态规则 | 在页面 JS 之前拦截，比 content script 遮罩可靠 |

### 6.2 模块架构

```
src/
├── background/            # service worker（大脑）
│   ├── tracker.ts         # 计时状态机
│   ├── ruleEngine.ts      # 规则匹配
│   ├── budget.ts          # 预算管理 + 重置
│   ├── blocker.ts         # DNR 动态规则控制 + 豁免计时
│   └── reporter.ts        # 聚合查询
├── content/
│   ├── nudge.tsx          # 非侵入提醒横幅（shadow DOM）
│   └── intent.tsx         # P1 意图打卡/落地询问遮罩
├── pages/
│   ├── popup/  options/  dashboard/  guide/
├── shared/
│   ├── types.ts  db.ts  defaults/templates.ts
```

### 6.3 计时引擎（全项目最难、最不能糊弄的部分）

**"正在使用页面 X"的定义**：`(该窗口聚焦) ∧ (X 是该窗口 active tab) ∧ (document 可见) ∧ (系统非 idle)`。四个条件任一不满足即停表。

**事件驱动 + 心跳兜底**（MV3 service worker 会被随时杀死，这是最大坑）：

1. 监听事件：`tabs.onActivated`、`tabs.onUpdated`（active tab 的 URL 变化）、`windows.onFocusChanged`、`idle.onStateChanged`
2. 每个事件关闭当前时间段（segment）：`duration = now - startedAt`，写入库，开启新段
3. **心跳**：`chrome.alarms` 每 30s 触发，把 `lastActiveAt` 写入 `chrome.storage.session`——只做水位标记，不做累加
4. **丢心跳补偿**：SW 复活后（任何事件或 `onStartup`）结算上一段时，`end = min(now, lastActiveAt + 60s 宽限)`，防止后台休眠虚增时间
5. **idle**：`chrome.idle` 阈值默认 60s（可配 30–300s）；`idle` / `locked` 状态 → 停表；恢复 active → 开新段
6. **多窗口**：只计聚焦窗口的 active tab（`windows.getLastFocused` 为准）；非聚焦窗口的播放视频不计（v1 简化，文档写明）
7. **隐身窗口**：spanning 模式下同一 SW 处理隐身/普通标签页，`tab.incognito` 打标记；未授权时如实显示缺口（见 3.7）

**数据写入**：每段写两条——`sessions`（明细行）+ `usage_daily`（date × category × host 的秒数累加）。报表只查聚合，下钻才查明细。

### 6.4 规则匹配实现

- 规则加载后预编译成 matcher 数组，按 specificity 降序排列，首个命中生效
- URL 解析用 `new URL()` + 前缀/通配符匹配（P0 不引 URLPattern，够用且好调试）
- popup 改判 = 给该 session 打补丁标记，聚合数随之修正

### 6.5 封锁实现

- 预算耗尽 → `declarativeNetRequest.updateDynamicRules` 给该类别下所有域名加 `redirect → chrome-extension://…/guide.html?url=…` 规则
- 豁免 → 暂时移除规则 + `alarms` 定 5 分钟后恢复
- 次日边界（`alarms` 定时）→ 清空全部封锁规则、预算归零、豁免次数归零
- badge：颜色 = 当前页类别色，文本 = 剩余预算分钟数（无预算类别显示累计分钟）

### 6.6 数据模型（Dexie）

```ts
// 配置类 → chrome.storage.local
Rule / Category / StudyTarget / Settings { budgets, dayCutoff, idleThresholdSec, exemptPerDay }

// 数据类 → IndexedDB
interface SessionRow  { id?, start, end, date, host, url, title, categoryId, ruleId?, intent?, exempt?, incognito? }
interface UsageDaily  { [date+categoryId+host]: { seconds, visits } }
interface ExemptLog   { date, count }
```

保留策略：sessions 90 天自动清理，usage_daily 永久（体积极小）。导出 = JSON 全量。

### 6.7 权限与隐私

- 权限：`tabs`、`idle`、`alarms`、`storage`、`declarativeNetRequest`、host `<all_urls>`
- 隐身数据同样全部本地存储——这是产品设计目的（监督自己的隐身浏览），首次开启授权时明确告知
- 隐私承诺写进 README 和 Options 首屏：**无任何网络请求、无账号、数据不出本机**；`<all_urls>` 是读取 URL 计时所需（自用 load unpacked，不上架则无审核问题；未来上架再评估 minimal host 集合）

### 6.8 测试与自验证（能不能自己测自己：能）

三层测试，前两层完全自动跑：

1. **单元测试（vitest + 假时钟）**：计时状态机是纯逻辑，把 `Date.now`、`chrome.*` 全部 mock 成可编程假件，就能确定性复现所有刁钻场景——SW 被杀 10 分钟后复活、idle 阈值边界、跨 dayCutoff、豁免计时器到点。规则引擎用表驱动测试（每条规则 × 一组 URL → 期望类别）。
2. **E2E（Playwright + 持久化 context + `--load-extension`）**：Playwright 官方支持加载未打包扩展。脚本化完整闭环：装扩展 → 多站点标签页切换/等待 → 切走模拟 idle → 读 popup UI 和 IndexedDB 断言计时 → 刷满预算断言重定向到引导页 → 点豁免断言放行 5 分钟 → 拨假时钟断言次日重置。我能自己写、自己跑、自己看截图验收。
3. **自用 dogfood（最终验收）**：MVP 完成后装进日常浏览器连续用一周——这层没法自动化，但它就是 M3 的验收标准本身。

关键设计约束：`chrome.idle` 的真实触发没法在测试里精确模拟，所以把 idle 判定收敛成**纯函数**（输入状态快照，输出停表/走表），单测全覆盖，真实浏览器只做冒烟验证。

# ADR-0009：v0.3 的隐身引导形态与数据管理决策

- 状态：Accepted（2026-09-06，v0.3 实现时）

## 决策 1：隐身提示用扩展图标 title + 设置页首屏，不用 badge 常驻

- **背景**：PRODUCT.md §3.7 计划"badge 常驻小黄点"。实现时发现 badge 文本位已被预算余量占用（v0.2 F4：badge 显示剩余分钟），两者冲突，且 Chrome badge 无"黄点"原语。
- **决策**：未授权时 SW 启动即 `chrome.action.setTitle` 追加警告（悬停可见）；设置页首屏常驻检测状态 + 三步图文指引 + 一键打开扩展管理页。授权状态用 `chrome.extension.isAllowedIncognitoAccess` 检测。
- **后果**：不打扰日常使用，同时不隐瞒缺口；badge 语义保持单一（预算余量）。

## 决策 2：明细清理挂在日切闹钟上，不新增 alarm

- sessions 90 天保留（data-model §2）。日切时本来就要 checkpoint + 重排 daycut alarm，顺带执行 `purgeSessionsOlderThan(90)`，避免多一个每日 alarm。

## 决策 3：导出 = 配置 + 三张表全量 JSON；清空 = storage.local.clear + Dexie.delete + 重播种默认配置

- 导出面向"换机/备份/自查"，直接给全量原始数据，不做报表化格式。
- 清空后调用 `ensureDefaults()` 恢复种子规则，让插件保持可用状态；双重 confirm 防误触。

## 决策 4：模板包按 pattern 去重追加，不覆盖

- 用户可能已改判/调整种子规则；导入只追加 pattern 不存在的条目，保证"一键导入"永不破坏现状。B站 `/video/*` 在「视频」包中默认娱乐、在「学习」包中映射 learning——两个包都包含它以便用户按需选择（以先导入者为准，重复导入被去重跳过；用户可手动调整）。

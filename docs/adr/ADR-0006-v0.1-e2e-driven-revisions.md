# ADR-0006：v0.1 计时引擎的四处实施修订（E2E 冒烟驱动）

- 状态：Accepted（2026-09-06）
- 修订对象：ADR-0003（部分语义细化）、key-algorithms.md §1.2/§1.3、architecture.md §5
- 触发方式：41 个单测全绿后，真机冒烟（e2e/smoke.mjs）连续三次 FAIL，取证定位。**单测全绿不等于真机可用，这条流程本身被证明必要。**

## 修订 1：tab-updated 参与开段 + 记账自愈

- **现象**：冒烟中 events 全部到达、activeTabs 正确更新，但 `current` 恒为 null，零记录。
- **根因**：状态机只在 `tab-activated` 开段。新 tab 激活瞬间 URL 是空白页（不可追踪），导航完成后只发 `tab-updated`——按旧规则永远不开段。此外 SW 早启动窗口期丢失的 `onActivated` 会让该 tab 在记账中永远不存在（无自愈路径）。
- **决策**：① `tab-updated`（adapter 已过滤为 active tab）对"聚焦窗口的 active tab"参与开段；② `tab-updated` 无条件 upsert 记账（自愈丢事件）；③ 开段统一加 `idleState === 'active'` 门禁（否则 idle 期间后台自动刷新会误开段）。
- **后果**：新增 E17/E18/E19/E20 用例；`TrackerState` 增加 `idleState` 字段。

## 修订 2：默认类别语义下沉 core（matchUrlOrDefault）

- **现象**：同一次冒烟中，规则外的站点（example.com）不产生段。
- **根因**：key-algorithms §2.2 设计了"无命中 → 默认类别"，但 background 只接了 `matchUrl`——"无规则"和"不可追踪"两种 null 被混为一谈。
- **决策**：core 新增 `matchUrlOrDefault(compiled, href, defaultCategoryId)`：规则命中 → 规则类别；无命中且 http(s) → 默认类别（无 ruleId）；其余协议（chrome:// 等）→ null。**这是 background deps.classify 的唯一正确实现**，杜绝两类 null 混淆。
- **后果**：新增 5 个用例；默认类别 v0.1 固定为 `neutral`（可配置化延后到 v0.3 options）。

## 修订 3：心跳的"证据断裂"语义（细化 ADR-0003）

- ADR-0003 只写了"心跳延长水位"。实施中明确为：心跳仅在 `current !== null && now - lastActiveAt <= 宽限 + 15s 抖动` 时前移水位；**跳档心跳（系统休眠后醒来）触发"按水位截断关段 + 立即重开"**，而不是无限延长。E3 用例固化该行为。

## 修订 4：配置变更触发全量 re-sync

- **现象**：冒烟中调大 idleThresholdSec 后，状态机 idleState 卡在旧值无法恢复。
- **根因**：`chrome.idle` 不会因为阈值变更重发 `idle-changed`，旧阈值下判定的 idle 永远不会纠正。
- **决策**：配置变更（storage.onChanged）→ `refreshAndSync()`：刷新规则/阈值并以新口径重建 idle 状态与窗口记账。SW 冷启动带快照时**不做** sync（保护进行中的段），仅浏览器级冷启动才全量对账。
